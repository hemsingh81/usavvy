- (event) Coaching path adopted (user confirmed via 'ca' after no objection to proposed defaults: coaching + spine-only + initiative altitude, with a likely epic-altitude drop-down later for Epic 3 Board and Epic 5 cohorts).
- (decision) User delegated stack/paradigm choice to Winston, with 3 explicit priorities: high performance, free/OSS tooling during dev phase (no deployment yet), and full-stack visibility (build FE+BE together, phased, visually verifiable each phase).
- (decision) AD-1 Paradigm: Modular feature-module layering internally, ports-and-adapters (hexagonal) at every external integration boundary (LLM, TTS, ASR, vector store, object storage). Considered pure microservices (rejected: premature ops overhead for solo/small team, free-tier dev phase) and pure layered-monolith-no-ports (rejected: PRD explicitly requires swappable LLM/TTS vendors, NFR-10/R-10, and user asked for config-driven runtime behavior — hexagonal ports directly satisfy both).
- (version) Backend: Node.js 22 LTS + TypeScript 5.x + Fastify 5.x. Chosen over Express (slower, less native schema validation) and over Python/FastAPI (splits language across FE/BE for a small team; Node's event-loop model fits the I/O-bound realtime/streaming profile better). Fastify picked specifically for throughput per user's 'high performance' priority.
- (version) Frontend: React 19 + TypeScript + Vite. Considered Next.js (rejected: SSR/routing conventions add complexity with no payoff for an authenticated SPA with no SEO/content-marketing surface).
- (version) Monorepo: pnpm workspaces. apps/web (frontend), apps/api (backend), packages/shared-types (DTOs, Beat schema, role/permission enums shared FE<->BE), packages/config (typed runtime config loader). Enables FE+BE to build together per user's visibility requirement and removes an entire class of drift (duplicated types).
- (version) Data: PostgreSQL 17 + pgvector extension for embeddings (one database instead of separate vector DB — boring/free/simple for dev phase; swappable to dedicated vector DB later behind the retrieval port if scale demands it). ORM: Drizzle (not Prisma) — explicit SQL-like schema-as-code, no generated-client magic, fits user's 'code in control, no dead code' preference.
- (decision) AD: Realtime transport is WebSocket only (ws / @fastify/websocket), not WebRTC. PRD section 19 says WebSocket/WebRTC; WebRTC is peer-to-peer media which nothing in the requirements actually needs (no live learner audio/video between cohort members — chat, polls, and a server-authoritative shared board suffice). Simplifies the realtime layer materially. Single-instance in-memory pub/sub for dev; Redis pub/sub adapter deferred until NFR-3 horizontal scaling is real.
- (decision) AD: Object storage behind a StoragePort — local filesystem or MinIO (free, S3-compatible, self-hosted via Docker) for dev, swappable to real S3/GCS adapter later without touching domain code.
- (assumption) [ASSUMPTION] LLM/TTS/ASR API calls themselves are NOT free regardless of provider (metered APIs) — 'free tools' applies to infra/frameworks/DB/storage, not model calls. Mitigation: a Mock generation/voice adapter ships first behind the same port so early phases (auth, board skeleton, course browsing) are buildable and visually demoable with zero API spend; a real provider adapter (Anthropic and/or OpenAI, TBD) swaps in once a phase specifically needs live generation.
- (decision) AD: RBAC module — roles SuperAdmin, Admin, Mentor, Student (per user's explicit request). Role set + default permission matrix ship as versioned seed config (packages/config), not hardcoded in business logic; per-user role assignment lives in the DB. JWT-based stateless auth (access+refresh tokens), custom-built (not a 3rd-party auth SaaS) to keep it free and fully owned per user's 'code in control' preference.
- (question) OPEN: 'Mentor' role has no defined scope in the PRD (which explicitly excludes live human tutors as a v1 non-goal, §3.3). Building the role into RBAC now (cheap, config-driven) but its actual permission set / feature surface needs a product decision — cohort facilitator/moderator? promoted peer mentor? reserved for a future release? Flagging as phase-blocker for whichever epic first exercises it, not for the spine itself.
- (decision) AD: Test structure mirrors source structure 1:1 in a parallel tests/ tree per app (tests/modules/x/... mirrors src/modules/x/...), per user's explicit guideline. Vitest for unit/component tests (fast, native ESM/TS, works across both apps), React Testing Library for FE components, Playwright for e2e (free, cross-browser, covers NFR-7).
- (decision) AD: No-dead-code enforcement — TypeScript strict mode + ESLint (no-unused-vars, no-unreachable, import/no-cycle) + Husky pre-commit gate, all free/OSS. Backed by bmad-code-review at the story level once implementation starts.

Renaming at the architecture layer to disambiguate: PRD 'Session' (Beats) -> LearningSession; PRD 'ScheduledSession' -> PlannedSession; CohortSession unchanged. Prevents two independently-built modules from conflating a calendar slot with a live playback run — same root cause the PRD validation flagged as a Glossary gap, fixed here for engineering purposes.
